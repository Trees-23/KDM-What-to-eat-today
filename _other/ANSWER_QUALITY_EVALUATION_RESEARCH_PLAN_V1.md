# 硬指标、RAG 指标与回答效果补充评测调研方案 V1.3

> **V1.1 当前执行范围（优先级高于本文其余旧设计）**
>
> 本轮目标只回答“300 题最终回复好不好”。保留既有 300 题硬规则结果作为只读底线；对每个 `passed` 题的最终回复仅做 **一次** LLM 回答效果评分，换算为 100 分。RAG 的 gold、Recall、Precision、MRR、nDCG、Top30/Top5 排序指标全部暂缓，不生成 RAG 分数，也不作为本轮失败条件。旧文中关于 RAG gold、人工标注、A/B 双评审、仲裁、60/30 题校准与 90 题重复稳定性检查的内容仅保留为未来专项研究参考，不得在本轮执行。

## 1. 这次要做什么

最新完整 300 题硬测试已经完成，来源固定为：

```text
_other/考试/检索重构真实场景考试包/结果/
  2026-08-15-intent-planner-300-005/
    new-results.jsonl
    runner.stdout.jsonl
    audits/
```

它已经检查了系统是否犯硬错误，例如路线错误、硬约束被绕过、证据或审计缺失、安全题乱答、禁止断言和无依据关系断言。本方案不重跑、不复制，也不改写这套考试的 `passed/failed` 结论。

接下来基于同一批 300 题，形成两张**相互独立、不能互相抵消**的本轮成绩单：

```text
既有 300 题运行
  -> 硬指标成绩单：有没有违反既定契约
  -> 回答效果成绩单：用户看完是否觉得贴题、清楚、好执行
  -> 并列展示二者，不合成一个掩盖问题的总分
```

其中：

- **硬指标**回答“系统有没有犯不能接受的错”；以现有 300 题运行的结果为准，只引用，不复判。
- **RAG 指标**回答“检索/候选/排序过程好不好”；它需要冻结的“应召回内容”标准，本轮暂缓为后续专项。
- **回答效果**回答“最终这段话对用户好不好用”；仅对 `status=passed` 的最终回答按场景评分为 0-100。

当前完整运行的 300 题均为 `passed`，因此都会进入回答效果评测。以后若来源运行含 `failed` 题，仍保留它的硬指标，但不对其补打回答效果分，只在报告中列出数量。

## 2. 为什么要分成三层

三层看的不是同一件事：

| 层 | 大白话 | 例子 | 结果怎么用 |
| --- | --- | --- | --- |
| 硬指标 | 有没有做错不能接受的事 | 明明查不到，却说“已验证搭配关系” | 任一硬错误必须单独处理，不能靠高分回答挽回。 |
| RAG 指标 | 有没有找对资料、排对顺序 | 好菜谱明明在候选里，却被排到第 20 名 | 用来定位检索、过滤、重排或证据链问题。 |
| 回答效果 | 用户能否看懂并马上行动 | 推荐虽然正确，但没说为何适合“清淡、30 分钟内” | 用来改善回答组织、理由、边界和表达。 |

因此，不允许出现“回答效果 95 分，所以忽略硬错误”的结论。RAG 专项完成前，也不得用没有 gold 的候选记录宣称“检索好或不好”。

## 3. 范围与边界

本方案做：

- 引用既有完整 300 题的硬测试结论；
- 从 `new-results.jsonl`、`runner.stdout.jsonl`、`frozen_questions.json`、`acceptance-report.json` 与 `audits/` 读取候选、路线、证据和最终回答；
- 对通过题的回答贴题程度、偏好贴合、证据/边界表达和可读性评分；
- 由单次 LLM 结构化评分产出低分原因；不使用人工逐题打分。

本方案不做：

- 不重跑 300 题，不调用线上检索服务，不重新生成回答；
- 不重新裁定实体 ID、图路径、PDS/Milvus 一致性、ConstraintSpec、硬范围或安全结论；
- 不以回答效果分推翻原始 `passed/failed`；
- 不把硬指标、回答效果、TTFT、总耗时或异常率混成一个总分；
- 不为缺失的候选、排序或 gold 字段编造 RAG 分数，也不在本轮补造 gold。

术语约定：

- `N/A`：该指标在这题没有业务意义，例如安全拒答题不应计算 Recall 或 nDCG；不是 0 分。
- `RAG_UNVERIFIED`：本应可计算 RAG 指标，但现有离线工件缺少候选、排序、冻结 gold 或必要审计，不能可靠计算；不是低分。
- `QUALITY_UNVERIFIED`：回答效果的必要输入或任一适用评分维度输出不完整。该题所有回答效果维度和 `total_score_100` 均写为 `null`，不计入任何回答效果平均值；不改变原题硬测试状态。

## 4. 三层指标总览

### 4.1 每个场景看什么

| 场景 | 硬指标成绩单（已有结果） | RAG 指标成绩单（后续专项，本轮不做） | 回答效果成绩单（新做） |
| --- | --- | --- | --- |
| S01-S03 菜谱、步骤、技巧 | 路线正确、目标内容正确、无禁止断言 | gold 命中、候选排序、证据完整/链接 | 是否直接回答、组织清楚、可照着做 |
| S04-S05 A/B 图关系 | 图路径真实、无关系伪造 | 图路径/关联结果命中、排序、证据可追溯 | 是否把关系解释成人话，并说清已知范围 |
| S06-S07 推荐 | ConstraintSpec、硬范围、Top30/Top5、硬约束不被绕过 | 候选覆盖、Top5 排序、证据可追溯；软偏好 nDCG 须有相关性标注 | 推荐是否贴合偏好、理由是否具体、能否做选择 |
| S05C、S08-S10 拒答/降级 | 正确拒答或降级、无幻觉、无禁止断言 | 排名指标 `N/A`；不伪造“应召回文档” | 拒答/限制是否清楚、有帮助、给出合适下一步 |

`S05C` 是 S05 的 C 卷零路径反例题，不是第 11 个独立场景。

### 4.2 硬指标成绩单

硬指标来自既有考试结论，至少展示下列项目及其来源题目：

- 题目覆盖率、通过/失败/阻塞数量；
- 路线契约、硬约束、图路径和安全规则的通过情况；
- 禁止断言数、无依据关系断言数、严格营养误报数；
- 已有的证据完整、证据链接、回答忠实度和故障降级检查；
- 缺失审计、缺失必填字段等使考试不可签收的情况。

硬指标没有“用其他分补回来”的机制。任何失败都按原考试规则保留，并指向原始题号、运行文件和审计 ID。

### 4.3 后续专项：RAG 指标成绩单（本轮不执行）

本节仅保存未来 RAG 专项的指标定义，便于后续在 gold 冻结后复用；它不是本轮实现、运行或验收的要求。本轮最终包只写 `RAG_DEFERRED`，不输出本节的任何数值或状态统计。

RAG 成绩单只衡量“过程效果”，不取代硬测试。对于有冻结 gold、候选顺序和必要审计的排名题，使用已有题库口径：

| 指标 | 看什么 | 适用条件 |
| --- | --- | --- |
| Recall@1/3/5 | 前 K 个候选找回了多少相关 gold | 题目有冻结相关 gold 与候选顺序。 |
| Precision@1/3/5 | 前 K 个候选中有多少比例相关 | 题目有冻结相关 gold 与候选顺序。 |
| Hit Rate@1/3/5 | 前 K 是否至少找到一个相关项 | 题目有冻结相关 gold 与候选顺序。 |
| MRR@5 | 第一个相关项是否排在前面 | 题目有冻结相关 gold 与候选顺序。 |
| nDCG@5 | 高相关项是否比低相关项排得更前 | 题目有分级相关性标签与候选顺序。 |
| 路由准确率 | 是否走了题目约定路线或受控回退 | 有路线契约和审计。 |
| 证据完整率 | 关键结论是否都有图事实或 PDS 正文支持 | 有最终回答与证据审计。 |
| 证据链接率 | 证据能否追溯到冻结的 parent/chunk/sourcePath | 有最终证据 ID。 |

计算口径沿用考试包的定义：Recall 是“已找回的相关 gold 数 / 全部相关 gold 数”；Precision 的分母固定为 K；MRR@5 为首个相关项的倒数排名；nDCG@5 使用 `2^relevance - 1` 的增益和对数折损。Hit Rate 只表示“有没有命中”，不能代替 Recall。

#### S06/S07 推荐的特别规则

S06/S07 要把“硬约束”和“软偏好”分开：

- ConstraintSpec、硬范围、Top30 -> Top5 两段式过程、硬约束不被高向量分绕过，属于既有硬指标；
- Top30 是否覆盖合适候选、Top5 是否排得更贴合，属于 RAG 指标；
- 推荐理由、偏好是否在回答中说清、用户能不能选，属于回答效果。

只有在题目已有冻结分级相关性标签，或 R1 新增并复核了标签后，才计算推荐题的 `nDCG@5`。新增标签采用 `0/1/2/3`：`0` 不相关或违反硬约束、`1` 满足基本任务、`2` 满足硬约束并体现一项重要软偏好、`3` 满足硬约束并体现该题所有关键软偏好/场景。标签必须由人工制定并在运行前冻结，不能看着模型排序临时修改。

若某道推荐题已验证硬范围为空，`NO_PREFERENCE_RESULTS` 是正确安全收敛：排名指标标为 `N/A`，不把空结果算成 Recall 0，也不退回全库伪造推荐。

#### 安全题的特别规则

S05C、S08、S09、S10 不计算 Recall、Precision、MRR、nDCG 或 Hit Rate。它们没有“应该召回的文档排序”，强行计算只会把“正确不找”误判为差检索。其正确拒答、零路径、无关系幻觉和故障降级继续由硬指标记录；回答效果只看表达是否清楚、有帮助。

### 4.4 回答效果成绩单

回答效果只面向 `status=passed` 的最终回答。每题使用场景化 0-100 分，便于比较趋势；不同题型权重不同，因此全体均分不能替代场景分。任何场景平均分低于 70，都必须在报告中单独显示。

评阅者先给每个适用指标 `1-5` 分：`1` 为明显不好用，`3` 为基本可用，`5` 为很好用。`null` 表示不适用，不以 0 分处理。

```text
单项折算分 = 指标权重 x (原始 1-5 分 - 1) / 4
题目总分 = 所有适用指标的单项折算分之和
```

| 指标 | 要回答的问题 | 适用场景 |
| --- | --- | --- |
| 任务完成度 | 是否直接、完整地回应了用户的问题？ | 全部 |
| 软偏好贴合度 | 是否在推荐顺序和理由中体现口味、场景、便利性等软偏好？ | S06/S07 |
| 证据表达 | 关键理由是否能对应已有证据，且没有把证据范围说大？ | S01-S07 |
| 边界表达 | 证据不足、未找到、图不可用或拒答时，是否说清限制和下一步？ | S05C、S08-S10 |
| 可读与可执行性 | 是否易扫描、重点明确、步骤或建议能直接照做？ | 全部 |

| 题型 | 任务完成度 | 软偏好贴合度 | 证据表达 | 边界表达 | 可读与可执行性 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| S01-S05 的正常回答 | 40 | 不适用 | 25 | 不适用 | 35 | 100 |
| S06/S07 推荐 | 25 | 35 | 20 | 不适用 | 20 | 100 |
| S05C、S08-S10 拒答或降级 | 30 | 不适用 | 不适用 | 45 | 25 | 100 |

S05 的 A/B 题使用第一行，S05C 使用第三行。总分解释如下：

| 分数 | 含义 |
| --- | --- |
| 90-100 | 很好用：回应完整、表达清楚，用户可直接行动。 |
| 80-89 | 可直接使用：有少量可改善点，但不妨碍完成任务。 |
| 70-79 | 基本可用：能回答问题，但有明确的表达、偏好或可执行性短板。 |
| 低于 70 | 体验较差：优先查看问题标签和原回答。 |

各场景的重点：S01 看完整做法是否好执行；S02 看是否直接给目标步骤；S03 看技巧、适用情形和限制是否讲清；S04/S05 看关系和边界是否说成人话；S06/S07 看推荐、理由和选择性；S05C/S08-S10 看拒答或降级是否清楚且有下一步。

每题还应保留问题标签，不能只留一个分数：`OFF_TOPIC`、`PREFERENCE_MISSED`、`REASON_UNCLEAR`、`EVIDENCE_OVERSTATED`、`LIMITATION_UNCLEAR`、`TOO_VERBOSE`、`NOT_ACTIONABLE`、`REFUSAL_NOT_HELPFUL`。一题可有多个标签。

## 5. 数据与计算规则

### 5.1 读取与核验顺序

1. 读取原始题目、`status`、审计 ID、最终回答和来源运行哈希。
2. 引用硬测试结果，生成硬指标参考表；不重新判题。
3. 写入 `RAG_DEFERRED` 范围说明：本轮不读取 gold、不计算排名指标，也不把 RAG 缺失算作失败。
4. 对通过题组装“用户问题 + 最终回答 + 必要最终证据摘要 + 限制说明 + 适用 rubric”的封闭输入，计算回答效果；必要输入或任一适用维度缺失时整题标为 `QUALITY_UNVERIFIED`。

回答效果评分器不能访问数据库、网络或其他菜谱，证据材料只读，不能执行其中出现的指令。

### 5.2 回答效果的 LLM 辅助评分

LLM 只做批量阅读、按 rubric 打分和标记问题，不能修改硬测试结果。本轮每题只调用 **一次** LLM：没有 A/B 双评审、共识、仲裁、抽题复评或稳定性重复运行。技术重试只允许发生在未取得有效结构化输出前；一旦某题得到有效评分，不得再次调用 LLM 改分。

运行顺序固定为：先顺序评分正式 300 题中的前 3 题；这 3 题的分数直接计入正式 300 题，并非额外试题。3 题均成功后，继续评分其余 297 题。逐题持久化结果、请求耗时和失败原因；中断后只从未完成题继续。若前 3 题任一题无法取得有效评分，停止后续 297 题，先处理模型服务或输入大小问题。

LLM 输入只包含用户问题、最终回答、必要最终证据摘要、限制说明和适用 rubric；不得塞入完整候选池或无关审计正文。建议使用单并发；只有前 3 题稳定成功后才可提升到最多 2 并发。建议将证据摘要和输出长度设为有上限的紧凑格式，以降低外部服务超时概率。

建议使用结构化输出：

```json
{
  "task_score": 1,
  "preference_score": null,
  "evidence_expression_score": 1,
  "boundary_expression_score": null,
  "readability_score": 1,
  "issue_tags": ["OFF_TOPIC"],
  "evidence_notes": [
    {
      "answer_excerpt": "回答中的关键理由",
      "verdict": "clear|overstated|unclear|not_applicable",
      "evidence_ids": ["parent_id:chunk_id"]
    }
  ],
  "confidence": "high|medium|low",
  "review_reason": "不超过 400 字的中文理由"
}
```

程序校验输出格式、分数范围、`null` 是否符合场景、权重公式、标签枚举及证据 ID 是否来自本题材料。偏题、无用、夸大或没说清限制的回答，不能因篇幅长或文采好而高分。

### 5.3 汇总规则

- 两张成绩单分别汇总：不计算“硬 + 回答效果”的综合总分；
- 硬指标按原考试通过条件、计数和来源题目展示；
- RAG 只写“本期暂缓：尚未建立冻结 gold”，不输出 RAG 有效题数、均分或低分；
- 回答效果按场景、难度、指标展示 100 分总分、各维分、有效题数和 `QUALITY_UNVERIFIED` 数量；
- `QUALITY_UNVERIFIED` 按题处理：该题各维分与 100 分总分均为 `null`，从所有回答效果均分分母排除，并单独列出原始服务错误和尝试次数；
- 回答效果全体分为有效题 100 分总分的算术平均值，同时必须展示 S01-S10 场景分和最低场景分；
- 任一场景回答效果低于 70，即使全体均分达到 80，也只能写“总体可用，但该场景待改进”。

## 6. 后续专项：人工标注与校准（本轮不执行）

本节只记录未来若要做 RAG 专项或人工对照时的候选研究方法。本轮没有人工逐题打分、60 题校准、30 题留出检查或任何人工通过门槛；也不以本节的条件阻塞 300 题单次 LLM 回答效果基线。

### 6.1 推荐相关性标签

1. 盘点 S06/S07 现有冻结 gold 是否已有可用于 `nDCG@5` 的分级相关性。
2. 对缺失的推荐题，人工按 `0/1/2/3` 标注候选相关性，记录硬约束与每项关键软偏好的满足情况。
3. 两位标注者独立标注，分歧题复核后冻结为版本化 gold。
4. 未冻结前只报候选覆盖、硬范围和已有可验证指标，不报告推荐 `nDCG@5`。

### 6.2 回答效果评分校准

1. 从既有 300 题按场景和 A/B/C 难度抽取 60 题作为校准集，每个场景 6 题，难度各 2 题；S05 中两道必须是 S05C。
2. 两位人工评阅者独立盲评，按同一 rubric 给 1-5 分并打问题标签。
3. 对同一 60 题运行 LLM 评分，比较人工与 LLM 的分数、标签和低分原因。
4. 调整 rubric 或评分提示词后，另抽取 30 道未参与调整的题作为留出检查集。
5. 分歧大的题由人工复核，保留最终判断和分歧原因。

V1 的实用验收目标：

| 项目 | 目标 |
| --- | --- |
| LLM 与人工各维分数相差不超过 1 分 | >= 80% |
| LLM 与人工的问题标签一致率 | >= 80% |
| 人工双评阅者各维分数相差不超过 1 分 | >= 80% |
| 留出检查集达到前两项 | 必须达到 |

未达到时，LLM 回答效果输出只能作为“待人工阅读的线索”，不能作为 300 题回答效果基线的结论。

## 7. 本轮输出工件

一次补充评测生成独立目录，只读取、不覆盖原始 300 题运行：

```text
_other/最终300测试/运行结果/<回答效果运行编号>/
  source-run.json                         # 300 题来源目录及文件哈希
  hard-scorecard-reference.json           # 已有硬测试结论的引用与来源，不重新判题
  rag-deferred.md                         # 本期不做 RAG 的范围与原因
  quality-scorecard.json                  # 每题单次回答效果分、标签、理由和技术状态
  integrated-summary.md                   # 硬指标与回答效果并列的汇总报告
  judge-input-manifest.json                # 评分输入证据与 rubric/judge 版本的哈希
```

`quality-scorecard.json` 每题至少记录：来源运行、题号、场景、难度、原始通过状态、最终回答哈希、审计 ID、适用指标、1-5 原始分、场景权重、由程序计算的 `total_score_100`、问题标签、置信度、`QUALITY_UNVERIFIED` 状态及原始错误、尝试次数、rubric/judge/schema 版本与 SHA-256。

`integrated-summary.md` 必须分别列出：

- 硬指标的原始通过结论、失败/阻塞与不可签收项；
- RAG 本期暂缓的原因和未来恢复前需要补齐的冻结 gold；
- 回答效果全体/场景/难度分、最低场景、低分题和常见问题标签；
- 推荐题、步骤题、拒答题各自的代表性好回答和待改进回答；
- 本轮低分只归因于回答贴题、偏好、证据/边界表达和可执行性；不得反推为检索或重排低分。

## 8. 分阶段调研与交付

### R1：盘点来源与评分输入

- 核对现有 300 题工件能否稳定抽取硬指标引用和回答效果输入；
- 输出 300 个题号、最终回答、审计 ID、证据摘要和适用 rubric 的完整性报告；
- 写入 RAG 暂缓说明，不盘点或构建本轮 gold；
- 输出两层字段映射和数据完整性报告。

### R2：单次 LLM 回答效果原型

- 生成硬指标参考表，不重跑、不复判；
- 为通过题组装封闭的回答效果评分输入，按场景权重换算为 100 分；
- 用正式题目中的前 3 题验证单并发请求、结构化输出、逐题落盘和续跑；
- 生成两层并列的初版汇总，不调用线上检索、不修改原始考试文件。

### R3：完成 300 题单次评分基线

- 前 3 题成功后，继续剩余 297 题；每题只保留一个有效 LLM 评分；
- 中断后只处理未完成题，不重打已完成题；
- 对 300 题生成回答效果基线，并按贴题、偏好、理由/边界和可执行性归因。

### R4：归档与未来专项准备

- 记录题库、rubric、judge、请求参数、耗时和错误版本；
- 归档硬指标引用、回答效果评分和 RAG 暂缓说明；
- 将 RAG gold 和重复稳定性检查列为后续独立专项，不影响本轮签收。

## 9. V1 签收条件

本轮两层补充评测满足以下条件，才可形成可复用基线：

- 来源只来自已完成的完整 300 题运行及其审计；
- 硬指标只引用原结果，不重跑、不更改原始通过/失败结论；
- 回答效果可追溯到来源回答、审计 ID、证据哈希、rubric 和 judge 版本；
- 正式 300 题每题恰有一次有效 LLM 评分，或以带原始错误的 `QUALITY_UNVERIFIED` 明确失败；
- 汇总报告并列展示硬指标和回答效果、场景、难度和问题标签，不能以一个好分数掩盖硬错误；
- RAG 暂缓说明存在，且没有伪造 RAG 分数；评分器失败不影响原题硬测试状态。
