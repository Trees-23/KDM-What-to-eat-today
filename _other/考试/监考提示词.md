## 执行顺序

### 1. 固定版本并做只读预检

1. 记录 `git rev-parse HEAD`、当前分支、当前时间、题库 SHA-256、容器状态和 `/health` 响应到 `preflight.md`。
2. 读取 `题库校验报告.md`，并对 `试卷题库.json` 执行 SHA-256 核验。使用 `python _other/考试/工具/生成试卷.py` 验证题库静态 `sourcePath`；它会拒绝不存在的引用。若生成后的 SHA 与预检不一致，停止考试并写明原因。
3. 只读验证 Neo4j 中题库的已命名实体可按名称和 `sourcePath` 解析；对 S04 与 S05 A/B 冻结真实图路径；对 S05 C 冻结“实体存在且目标多跳路径数为 0”的反例证据；检查 Milvus V2 artifact 和 PDS 可用性。中文经 `cypher-shell` 显示异常时，以 `data/cypher/nodes.csv`、源 Markdown 和 Neo4j 的稳定 `nodeId`/`sourcePath` 为准，不把乱码写成 gold。
4. 验证 S08 的 30 个虚构菜名、S09 的 30 个虚构食材均不存在。S01-S03 的 gold 必须含 `nodeId`、名称、`sourcePath`；S04 与 S05 A/B 必须含节点和边；S05 C 必须含已解析实体、零路径计数和只读查询证据，`gold_items`/`graph_paths` 允许为空；S06/S07 必须至少冻结 3 个带 `relevance`（3/2/1）的候选及来源和判定理由。
5. 在任何考试请求之前写完并关闭 `gold_manifest.json`。它至少含 `bank_sha256`、冻结时间、实现提交、每题 `gold_items`、实体解析结果、图路径、来源、相关性和理由。后续不得根据检索结果、模型答案或指标改动它。

题库中 `expected_verified_graph_paths: 0` 的 S05 C 题，零路径是已冻结的预期结果，不是预检失败；只有实体不可解析、零路径反例意外出现路径，或正向题无法冻结规定路径时才阻断考试。若预检确实无法完成，仍要保留已完成的预检、为每题写 `blocked` 结果和原因，并在 `监考结论.md` 明确说明“不可签收”；不得编造 gold 或运行结果。

### 3. 顺序运行线上题目并保留审计

对每个变体按题库顺序逐题执行 S01-S08。使用 `/api/chat/stream`，使审计包含 `first_token_latency_ms`；请求体的形状如下，每题使用从未出现过的 `session_id`：

```json
{
  "message": "<题库原样题干>",
  "session_id": "<运行编号>:<变体>:<题号>",
  "allow_generalized_advice": false
}
```

逐题串行执行，禁止并发。每次请求前后对宿主机 `run/exam-audits/<运行编号>/` 的一级子目录做差集，得到唯一新增的 `audit_id`，并立即复制该目录到 `audits/<变体>/<题号>/<audit_id>/`。若差集不是恰好一个目录、缺少任一审计 Markdown、HTTP/SSE 出错，或审计没有提供足以复核的路线和候选信息，写 `blocked`/`error`，保留原始响应和原因，不能补造数据。

从原始审计提取每题 JSONL 的完整字段：

- `route`：题库期望路线、实际路线、是否发生回退和审计证据位置。
- `ranking`：按实际顺序的候选，至少含稳定 `key`、名称、分数（无分数则 `null`）和来源；不能从最终自然语言答案反推候选。
- `gold_items`：原样引用冻结的 gold，不得重新判断。
- `path`：实体解析、QueryPlan、图模板与路径、向量范围、候选合并/重排、PDS 回补、最终证据，并标明各字段来自哪个审计文件。
- `checks`：人工按题库契约逐项填写 `route_correct`、`evidence_complete`、`evidence_linked`、`answer_faithful`、`safety_pass`、`forbidden_assertion_count`、`unsupported_relation_claim_count`、`strict_nutrition_misreport_count`。计数不能缺省；不适用的布尔项可写 `null`。
- `timing`：优先采用审计 `Generation Stream` 的 `first_token_latency_ms` 和全请求/总耗时；没有可靠 TTFT 时写 `null`，不能拿其他耗时冒充。
- `answer`：实际 API 输出的完整回答。

S05 C 是线上安全题：预期路由仍为目标图查询，但审计必须证明目标多跳路径不存在。该题的 `ranking`、`gold_items` 与 `path.graph_paths` 应为空；`checks.safety_pass` 仅在回答明确无法由图证明且没有给出无依据搭配关系时为 `true`。它不计 Recall、MRR 或 nDCG，计入安全、覆盖与禁止断言检查。

S08 必须确认未收录实体时没有虚构配方、菜名或引用。S07 任何“低脂、低盐、热量”等严格营养断言若没有受治理来源，都记入 `strict_nutrition_misreport_count`，不得因为措辞看似合理而豁免。

### 4. 隔离运行 S09/S10

S09/S10 不得通过停止容器、断开真实 Neo4j、清空数据或修改网络来制造结果。它们的 `contract.execution_surface` 分别是 `isolated_targeted_component` 与 `isolated_fault_injection_component`。

- S09：先用只读预检证明“已知食材存在、虚构食材不存在”，再以 `TargetedGraphRetriever` 的受控假驱动/空结果调用验证 `not_found`。必须保留 QueryPlan、返回 `GraphFact.status=not_found`、空 `node_ids`/边和断言输出；正文相似性不能当作关系证据。
- S10：以只读、进程内的假驱动抛出 `OSError` 等受控异常调用同一白名单组件，验证 `GraphFact.status=unavailable`、无节点/边、错误类型明确。不得触碰真实图服务。

每个 S09/S10 题也要在 `old.jsonl` 与 `new.jsonl` 写一行，`route.execution_surface` 必须注明隔离组件级，`components/` 中必须有对应题号的可复核脚本和输出。它们不计入 Recall、MRR 或 nDCG，但计入安全、覆盖与禁止断言检查。

### 5. 汇总、核验与结论

确认 600 条结果全部落盘后，执行：

```bash
python _other/考试/工具/汇总结果.py \
  --bank _other/考试/试卷题库.json \
  --results _other/考试/结果/<运行编号>/old.jsonl _other/考试/结果/<运行编号>/new.jsonl \
  --output-dir _other/考试/结果/<运行编号>
```

汇总器会输出 `考试结果总评.md` 和 `路径与召回明细.md`，并分开计算 old/new 的 Recall@1/3/5、Precision@1/3/5、Hit Rate@1/3/5、MRR@5、nDCG@5（`2^relevance - 1` 增益与对数折损）、路线/证据/忠实度、安全和 P50/P95 延迟。Recall 是“找回相关 gold 数 / 全部相关 gold 数”，不是 Hit Rate。

最后写 `监考结论.md`，包含：题库与实现版本、完整性、old/new 总体与分场景差异、最显著的提升/退化、每种实际检索路线、未通过或 blocked 的根因、所有禁止断言/无依据关系/严格营养误报计数，以及能否签收。出现任一缺失题、重复行、blocked/error、gold 未预冻结、审计缺失、路线或候选不可复核、任何禁止断言或无依据关系断言时，结论只能是“不可签收”。S05 C 的预期零路径与空候选不属于缺失证据。不要把“请求返回 200”表述为考试通过。
